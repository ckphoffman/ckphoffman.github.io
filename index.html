MSc dissertation · Research

Financial Time-Series Anomaly Detection

Evaluated anomaly-detection methods on 2,910,814 one-minute observations across 30 US equities, using TSB-AD to compare close-price inputs with multivariate market bars.

Project details

Built an evaluation framework around weak proxy labels, intraday-adjusted robustness checks, score-tail precision and forward-risk enrichment. Compared price-only signals with inputs including volume, trade count and VWAP.

The findings support anomaly detection as a market-monitoring and risk-control aid; the study does not establish profitability or directional price prediction.

COMP4039 coursework · Database web application

Police Traffic Management System

A PHP and SQL coursework application that connects people, vehicles and traffic incidents in one searchable workflow. Separate officer and administrator roles support incident reporting, fine association and audit-log review.

Project details

Incident reporting. Record an incident with its date, description, offence, vehicle and person. Reuse existing vehicle and person records or add new ones as part of the reporting workflow, then retrieve and edit the report.

Search and retrieval. Find incidents by ID, date range, vehicle registration, person name, licence number or officer name. Dedicated people and vehicle searches provide access to related records.

Role-based workflows. Officers record and retrieve operational data; administrators can also create officer accounts, associate fines with incidents and review audit logs. Account features include sign-in, password changes and logout.

Relational data and audit trails. Model accounts, officers, people, vehicles, ownership, incidents, offences, fines and audit logs. SQL triggers record account and incident changes, while PHP functions log record reads. Administrators can filter audit records by user, action, table and date range.

Delivery. Built with PHP, MySQLi, HTML, CSS and JavaScript, with a Docker Compose environment using MariaDB. Delivered SQL setup files, a user manual and a technical manual covering installation, data flow and database design. The application runs with a PHP web server and database.

YouTube Vocabulary Learner

My most complete project — a three-part system I iterated on from a single extension into a full-stack app.

  1. Chrome extensioncaptures uploaded (non-auto) subtitles from the video you're watching
  2. Node + Express APItokenises text, stores videos, sentences & word counts in SQLite
  3. React + TypeScript web appbrowse words, read every sentence they appear in, jump the embedded player to that moment
  • Counts each word once per video, so rewatching doesn't inflate frequencies.
  • Concordance view: every subtitle line containing a word, highlighted, grouped by video.
  • Click a sentence → the embedded YouTube player seeks to that timestamp.
  • Favourites, sorting by frequency / date / alphabet, and filters.
  • v1 was a standalone extension with IndexedDB storage and a hand-written lemmatiser (am/is/are → be); v2 split it into extension, API and web app.
