Anomaly Detection for Automated Trading

MSc dissertation, University of Nottingham

Automated trading needs an early warning when markets behave abnormally, but real market data has no “correct answer” labels to test against.

What I did
Risk-aware TSB-AD benchmarking comparing a close-only representation with a multivariate bar of OHLC, volume, trade count and VWAP. A custom execution layer adapts the TSB-AD model wrappers to unlabelled equity bars without modifying the upstream implementations. Evaluation combines weak proxy labels, intraday-adjusted robustness checks, top-1% score precision, consensus-event inspection, and current and forward risk-enrichment ratios.
Result
LSTMAD was strongest with both representations; multivariate inputs improved neural models, especially LSTMAD and USAD, while close-only SR and Sub_KNN stayed competitive for return-driven stress. High-score periods coincided with higher stress and larger next-30-bar moves.
Takeaway
Anomaly detection is most defensible as a risk-aware monitoring layer for automated trading. The study does not claim profitability or directional price prediction.
Stack
Python, PyTorch, TSB-AD, time series, risk analysis

Police Traffic Management System

COMP4039 coursework, database web application

PHP and MySQLi, MySQL and MariaDB, JavaScript, SQL triggers, Docker Compose

Situation
A traffic-police team needs one searchable workflow that connects people, vehicles and traffic incidents, with separate officer and administrator roles.
What I did
Modelled accounts, officers, people, vehicles, ownership, incidents, offences, fines and audit logs. Built incident reporting that reuses or adds vehicle and person records; search by ID, date range, registration, name, licence number or officer; and admin tools to create officer accounts, associate fines and review audit logs. SQL triggers record account and incident changes, while PHP functions log record reads.
Result
A Docker Compose environment with MariaDB, SQL setup files, a user manual and a technical manual covering installation, data flow and database design.
Takeaway
Controls belong in the data layer: role separation, linked records and an audit trail administrators can filter by user, action, table and date.

YouTube Vocabulary Learner

My most complete project, a full-stack product

I wanted to learn English vocabulary from the videos I actually watch, with every word shown in its real context.

PartWhat it does
Chrome extensionCaptures uploaded (non-auto) subtitles from the video you are watching.
Node and Express APITokenises text, stores videos, sentences and word counts in SQLite.
React and TypeScript web appBrowse words, read every sentence they appear in, jump the embedded player to that moment.
  • Counts each word once per video, so rewatching does not inflate frequencies.
  • Concordance view: every subtitle line containing a word, highlighted, grouped by video.
  • Click a sentence and the embedded YouTube player seeks to that timestamp.
  • Favourites, sorting by frequency, date or alphabet, and filters.

v1 was a standalone extension with IndexedDB storage and a hand-written lemmatiser (am, is, are to be). When it outgrew that, v2 split it into extension, API and web app: start small, use it for real, and know when to rebuild rather than patch.

Chrome MV3, Express, SQLite, React 18, TypeScript, Vite, Tailwind
