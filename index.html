MSc dissertation · Research硕士论文 · 研究

Anomaly Detection for Automated Trading面向自动化交易的异常检测

PythonPyTorchTSB-ADTime seriesRisk analysis
Situation背景
Automated trading needs an early warning when markets behave abnormally — but real market data has no "correct answer" labels to test against.
自动化交易需要在市场异常时提前预警——但真实市场数据没有“标准答案”可以用来检验模型。
What I did我做了什么
Risk-aware TSB-AD benchmarking on 2,910,814 one-minute bars from 30 US equities in 2025, comparing a close-only representation with a multivariate bar of OHLC, volume, trade count and VWAP. A custom execution layer adapts the TSB-AD model wrappers to unlabelled equity bars without modifying the upstream implementations. Evaluation combines weak proxy labels, intraday-adjusted robustness checks, top-1% score precision, consensus-event inspection, and current and forward risk-enrichment ratios.
在 2025 年 30 只美股、共 2,910,814 根一分钟 K 线上做风险导向的 TSB-AD 基准测试，比较“仅收盘价”与“多维 K 线（OHLC、成交量、成交笔数、VWAP）”两种表示。自建执行层，在不改动上游实现的前提下，让 TSB-AD 模型适配无标签的股票数据。评估结合弱代理标签、日内调整后的稳健性检验、前 1% 分数精度、共识事件检查，以及当期与前瞻风险富集比。
Result结果
23 model–representation combinations across all 30 tickers produced 690 aligned score vectors with no failures. LSTMAD was strongest with both representations; multivariate inputs improved neural models, especially LSTMAD and USAD, while close-only SR and Sub_KNN stayed competitive for return-driven stress. High-score periods coincided with elevated stress and larger next-30-bar moves.
23 种模型–表示组合覆盖全部 30 只股票，得到 690 组对齐的分数向量，零失败。LSTMAD 在两种表示下都最强；多维输入提升了神经网络模型（尤其 LSTMAD 和 USAD），而仅收盘价的 SR、Sub_KNN 在收益驱动的压力上依然有竞争力。高分时段与当期压力上升、之后 30 根 K 线的更大波动高度吻合。
Takeaway结论
Anomaly detection is most defensible as a risk-aware monitoring layer for automated trading — the study does not claim profitability or directional price prediction. Supervised by Professor Xu Kai; submitted May 2026.
异常检测最站得住脚的定位，是自动化交易中的风险监控层——本研究不主张盈利能力或价格方向预测。导师：Xu Kai 教授；2026 年 5 月提交。

COMP4039 coursework · Database web applicationCOMP4039 课程项目 · 数据库网页应用

Police Traffic Management System警务交通管理系统

PHP / MySQLiMySQL / MariaDBJavaScriptSQL triggersDocker Compose
Situation背景
A traffic-police team needs one searchable workflow that connects people, vehicles and traffic incidents — with separate officer and administrator roles.
交警团队需要一个可检索的统一流程，把人员、车辆和交通事故关联起来——并区分警员与管理员两种角色。
What I did我做了什么
Modelled accounts, officers, people, vehicles, ownership, incidents, offences, fines and audit logs. Built incident reporting that reuses or adds vehicle and person records; search by ID, date range, registration, name, licence number or officer; and admin tools to create officer accounts, associate fines and review audit logs. SQL triggers record account and incident changes, while PHP functions log record reads.
建模账户、警员、人员、车辆、所有权、事故、违法类型、罚款与审计日志。实现事故上报（可复用或新增车辆与人员记录）；按编号、日期范围、车牌、姓名、驾照号或警员检索；以及管理员创建警员账户、关联罚款、查看审计日志的功能。SQL 触发器记录账户与事故的变更，PHP 函数记录数据读取。
Result结果
A Docker Compose environment with MariaDB, SQL setup files, a user manual and a technical manual covering installation, data flow and database design.
交付基于 MariaDB 的 Docker Compose 环境、SQL 初始化文件、用户手册，以及涵盖安装、数据流与数据库设计的技术手册。
Takeaway结论
Controls belong in the data layer: role separation, linked records and an audit trail administrators can filter by user, action, table and date.
控制应当落在数据层：角色分离、关联记录，以及管理员可按用户、操作、数据表和日期筛选的审计轨迹。

Featured · Full-stack product代表作 · 全栈产品

YouTube Vocabulary LearnerYouTube 词汇学习器

Chrome MV3ExpressSQLiteReact 18TypeScriptViteTailwind
Situation背景
I wanted to learn English vocabulary from the videos I actually watch, with every word shown in its real context.
我想从自己真正在看的视频里学英语单词，并看到每个词在真实语境里的用法。
What I did我做了什么
v1 was a standalone extension with IndexedDB storage and a hand-written lemmatiser (am/is/are → be). v2 split it into a Chrome extension that captures uploaded subtitles, a Node + Express API that tokenises text and stores videos, sentences and word counts in SQLite, and a React + TypeScript web app.
v1 是一个使用 IndexedDB 存储、带手写词形还原（am/is/are → be）的独立扩展。v2 拆分为三部分：抓取上传字幕的 Chrome 扩展、负责分词并把视频、句子和词频存入 SQLite 的 Node + Express API，以及 React + TypeScript 网页应用。
Result结果
A concordance view of every subtitle line containing a word, grouped by video; click a sentence and the embedded player seeks to that moment. Favourites, sorting and filters — and each word counts once per video, so rewatching doesn't inflate frequencies.
例句索引视图按视频分组列出包含某词的每一行字幕；点击句子，内嵌播放器即跳转到该时刻。支持收藏、排序与筛选——每个词在同一视频中只计一次，重复观看不会虚高词频。
Takeaway结论
My most complete project: start small, use it for real, and know when to rebuild rather than patch.
我最完整的项目：从小处开始、真实使用，并判断何时该重构而不是打补丁。
