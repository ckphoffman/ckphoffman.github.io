③为什么要编译好几次？— 链接的奥秘

LaTeX 是单遍处理器：从头读到尾。当它读到 \ref{fig:1} 那一行时，fig:1 的图都还没出现，它根本不知道编号是几、页码是几。怎么办？把信息先写到磁盘，下次再读回来——这就是「链接」的全部秘密。

1

第一遍 pdflatex document.tex

正常排版。遇到 \label{fig:1} 时，把「fig:1 → 编号 1，第 1 页」写入 document.aux；遇到 \ref{fig:1} 时不知道答案，先输出占位符 ??，并在日志里抱怨「LaTeX Warning: Reference 'fig:1' on page X undefined」。

源代码
参考\ref{fig:1}
PDF 输出
参考 ??
B

BibTeX 介入 bibtex document（若有参考文献）

这是另一个独立的程序。它读 .aux 文件里 LaTeX 写下的 \citation{Knuth1984} 记录，去 .bib 数据库找到对应条目，按 .bst 样式文件格式化后写出 document.bbl。LaTeX 自己其实不懂 BibTeX 格式，只会读已经处理好的 .bbl。索引（makeindex）和术语表（glossaries）流程类似。

2

第二遍 pdflatex document.tex

启动时先把 .aux 全部读入内存。这一次，当再遇到 \ref{fig:1}，它已经知道答案了——直接打印「1」。\cite{Knuth1984} 也变成 [1]。目录页知道每一章在第几页。hyperref 此时把这些引用全部包装成 PDF 内可点击的链接。

3

有时还需要第三遍

第二遍补回的引用文字长度变了（比如「??」一个字符变成「[15]」四个字符），可能挤动后面的行、改变某些 label 的页码——这又让 .aux 改变。所以工具链会一直跑直到 .aux 收敛、不再变化。这就是 latexmk 之类的工具默默替你做的事。

④点击「编译」之后，后台到底执行了什么

把刚才的演示按顺序拆开看，下面是「点了编译按钮」到「PDF 出现」之间的每一步：

1

启动 TeX 引擎

编辑器（TeXShop、Overleaf、VSCode + LaTeX Workshop……）只是个外壳，它在后台调用了一个独立的可执行文件——通常是 pdflatex、xelatex 或 lualatex。本质上是 pdftex/xetex/luatex 这些引擎，加上预先加载的 LaTeX 宏包。

引擎初始化字体表、catcode 表、内存池，把 LaTeX 格式文件（.fmt，一份已经预编译好的「热启动镜像」）读进来——这就是为什么编译总是一开始就「噌」一下，因为 LaTeX 内核已经预先冻干了。
2

词法分析：字符变 token

引擎逐字符读源文件，根据每个字符的 catcode（类别码）将其归类。共 16 种：\ 是「转义」、{} 是「分组」、$ 是「数学切换」、% 是「注释」、字母是「字母」、空格是「空格」……

catcode 可以重定义。这就是 verbatim、listings 等环境能让 \ 等特殊字符「失效」的原理——它们临时改了 catcode 表，让 \ 不再是转义符。
3

宏展开：高层命令 → 底层指令

LaTeX 命令大多是「宏」——本质是文本替换规则。比如 \section{介绍} 会被展开成数十条原始 TeX 指令：「跳过一段垂直空白；切到加粗大字号；查询 .aux 中的章节编号；把『1』和『介绍』拼到一起；把这个组合写到 .toc；恢复正文字体……」

TeX 严格区分 展开（expansion，把宏替换成它的定义）和 执行（execution，调用排版原语）。两个阶段交错进行——这就是 TeX 编程那么烧脑的根源。
4

排版：盒子与胶水

所有内容最终都成为「盒子」（box）。盒子之间用「胶水」（glue，一种带弹性的空白）连接。

  • 水平盒子（hbox）：字形一字字排成一行
  • 数学盒子：包含上下标、分数线、定界符的复合结构
  • 图形盒子：外部图片，记录大小、位置和缩放参数
  • 垂直盒子（vbox）：把多行段落或图、表、标题堆成一页
所有 LaTeX 排版问题最终都是「盒子拼图」问题。理解了这点，就理解了为什么 \hspace/\vspace/\hfill/\vfill 在 LaTeX 里那么核心。
5

断行与分页

段落由 Knuth-Plass 全局断行算法处理：把整段当一个整体，尝试所有可能的断行组合，挑出「丑陋度」（badness，由字间距偏差、连字符次数、行尾参差等加权）最低的那一种。这就是 LaTeX 排版比 Word 美观的根本原因——Word 是逐行贪心，LaTeX 是全段全局优化。

分页由「输出例程」（\output）触发：当垂直方向堆叠超过一页高度，它把当前内容打包成一页 PDF 输出，剩下的留给下一页继续。

6

写副产品文件

排版过程中遇到 \label、\section、\cite 都会顺手往磁盘写一笔——这些就是下一遍编译需要的「记忆」：

document.aux 里典型的一行：
\newlabel{fig:1}{{1}{1}{示例图片}{figure.1}{}}
含义：标签 fig:1 的编号是 1，在第 1 页，标题是「示例图片」，对应的 PDF 锚点是 figure.1。
7

外部工具：BibTeX / biber / makeindex

主程序之外还有几个独立工具，各管一摊：

  • bibtex / biber — 读 .aux 里的 \citation，从 .bib 数据库找条目，按 .bst 样式生成 .bbl
  • makeindex / xindy — 读 .idx 里的索引词条，排序、去重，输出 .ind
  • makeglossaries — 处理 glossaries 宏包的 .glo → .gls

这些工具完全独立于 LaTeX 引擎，靠文件交换数据。这是 1980 年代的设计——但因为接口稳定，至今仍在用。

8

再编译——完成链接

带着完整的 .aux、.bbl、.toc 信息再跑一遍 pdflatex。这一次：

  • \ref{fig:1} 不再是 ??，而是 1
  • \cite{Knuth1984} 变成 [1]
  • 目录页知道每一章在第几页
  • hyperref 把每个 \ref/\cite/目录项 包装成 PDF 注释流里的可点击链接

这一遍如果 .aux 又变了（引用文字撑长了行、把后面的章节推到下一页……），就再来一次，直到 .aux 不再变。latexmk 就是替你做这件事的工具。

9

写出 PDF

pdflatex 边排版边直接生成 PDF 字节流。每个字体子集、每张图、每页的内容、每条注释（包括超链接）都是一个独立的 PDF 对象（编号 1, 2, 3…）。最后写一张 xref 表（cross-reference table，对象索引），列出每个对象在文件里的字节偏移。

巧合的是，PDF 内部的「xref 表」本身也是一种「链接机制」——它让阅读器能直接跳到第 N 个对象，不必把整个文件扫一遍。LaTeX 给你做了文档层面的链接（\ref→编号），PDF 自身做了文件层面的链接（对象号→字节偏移）。

— LaTeX 编译之旅 完 —

本演示模拟的是 pdflatex 的典型流程。XeLaTeX、LuaLaTeX 在字体处理（OpenType、Unicode）和脚本能力上更现代，但骨架就是这些。
