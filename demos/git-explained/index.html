Git 的工作原理

把 Git 想成一台快照机器：工作区负责改文件，暂存区挑选下一次快照，本地仓库存对象和引用，远程仓库负责同步。

      03

      Git 底层的四个核心概念

      1

      对象是不可变内容

      Git 把文件内容、目录结构和提交信息存成 blob、tree、commit。内容一变，哈希就变。

      2

      提交是完整快照

      每次 commit 记录的是项目的一棵目录树，不是简单的补丁。相同内容会复用已有对象。

      3

      分支是轻量指针

      新建分支通常只是在 refs 里多了一个名字，所以创建和切换分支很快。

      4

      同步靠对象和引用

      push 和 fetch 传输缺失对象，再更新远端或本地的分支引用。

      04

      常见命令对应的内部动作

      命令 内部发生什么 影响区域
      git add file 把当前文件内容写成 blob，并把路径到 blob 的映射放进 index。 工作区 → 暂存区
      git commit 把 index 组装成 tree，创建 commit 对象，让当前分支指向它。 暂存区 → 本地仓库
      git branch name 创建一个新的 refs/heads/name，初始指向当前提交。 本地引用
      git switch name 更新 HEAD 指向的分支，并把工作区恢复成该提交的快照。 HEAD、工作区
      git merge name 如果能快进就移动分支指针，否则创建一个有两个父提交的 merge commit。 提交图、本地引用
      git push 上传远端缺少的对象，再请求远端更新对应分支引用。 本地仓库 → 远程仓库
